# M4 — Terminal Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pestaña Terminal por proyecto con shells reales (`node-pty` + `xterm.js`), sesiones vivas entre pestañas, log capado y fila en `executions` por sesión.

**Architecture:** `terminal.service.ts` en main posee los procesos pty, el ring en memoria y el log. El renderer solo envía teclas/resize a sesiones existentes y recibe salida por dos canales push declarados. El cwd y el shell los resuelve siempre main.

**Tech Stack:** Electron 45, `node-pty`, `@xterm/xterm`, `@xterm/addon-fit`, Zod 4, Zustand, `node:sqlite`.

**Spec:** `docs/superpowers/specs/2026-10-23-m4-terminal-design.md`

## Global Constraints

- **Sin tests automatizados** (CLAUDE.md regla 1): ningún test, script ni dependencia de testing. Verificación del agente = `npm run check` (typecheck + lint) tras cada tarea; las pruebas funcionales las hace el usuario a mano.
- Procesos solo ejecutable + array de args, nunca `shell: true`. Sin canal genérico `invoke(channel, payload)` ni `runCommand(string)`; el renderer nunca envía cwd ni comando.
- Salida del pty pasa por `redact()` (`src/main/services/git-errors.ts`) antes de ir al log.
- Migraciones solo hacia adelante: nueva `m003` en `src/main/db/migrations/index.ts`, sin editar m001/m002.
- Constantes (un solo sitio): `TERMINAL_LOG_CAP_BYTES = 5 * 1024 * 1024`, `TERMINAL_RING_BYTES = 1024 * 1024`, `TERMINAL_MAX_SESSIONS = 8`.
- Errores esperados: `StewardServiceError` con código. Imports de tipos con `import { type X }`. Comentarios solo para el porqué.
- Commits: Conventional Commits, solo cuando el usuario lo pida. `CHANGELOG.md` se actualiza en cada commit (Unreleased, etiqueta M4). `vault/` y `graphify-out/` nunca se commitean.
- Tras cualquier cambio de código: `graphify update .`.

## Review Focus

1. Shell configurado que no existe o sale al instante: error claro o sesión finalizada con exit code, sin quedar "running" (Tarea 4, 5).
2. Comando que inunde la salida: log se detiene en 5 MB, `truncated` visible, memoria acotada, UI no se congela (Tarea 4, 7).
3. Proyecto o repo borrado con sesiones vivas: se matan las sesiones; la fila `executions` borrada por cascada no hace fallar el cierre (Tarea 4, 6).
4. `write`/`resize` sobre sesión ya muerta o inexistente, y resize con 0 cols/rows (pestaña oculta): rechazado o ignorado sin lanzar (Tarea 2, 4).
5. Recarga del renderer (Ctrl+R / HMR) con sesiones vivas: `attach` repinta el ring; no hay listeners duplicados (Tarea 7).

**Files:**

**Interfaces:**
- Produces, en `terminal.ts`:

  - Inputs con su schema y tipo: `TerminalCreateInput {projectId, repositoryId, cols, rows}`, `TerminalWriteInput {sessionId, data}` (data ≤ 64 KB), `TerminalResizeInput {sessionId, cols, rows}` (enteros 1–1000), `TerminalSessionIdInput {sessionId}` (para close/attach), `TerminalListInput {projectId}`, `TerminalSettings {shellPath: string|null, shellArgs: string[]}`, `TerminalGetSettingsInput {projectId}`, `TerminalSetSettingsInput {projectId, shellPath, shellArgs}` (shellPath absoluto o null; args ≤ 16, cada uno ≤ 256 chars).

Los canales push **no** entran en `IPC_CHANNELS` (el chequeo de cobertura exige un handler por cada uno).

### Task 4: terminal.service

**Files:**
- Create: `src/main/services/terminal.service.ts`, `src/main/services/terminal-shell.ts`

**Interfaces:**
- Consumes: repos de la Tarea 3, `redact`, `validateExistingDirectory`/`normalizeAbsolutePath` de `security/paths.ts`, repo de repositorios.
- Produces en `terminal-shell.ts`: `resolveShell(settings: TerminalSettings): { file: string; args: string[] }` (config válida, o autodetección: Windows pwsh → powershell → cmd comprobando existencia en `PATH`/`System32`; Unix `$SHELL` o `/bin/sh`). Lanza `StewardServiceError('SHELL_NOT_FOUND', …)` si `shellPath` no existe o no es archivo.
- Produces en `terminal.service.ts`:
  - `createTerminalService(deps: { database: StewardDatabase; emitData(e: TerminalDataEvent): void; emitExit(e: TerminalExitEvent): void }): TerminalService`.
  - `TerminalService`: `create(input: TerminalCreateInput): TerminalSession`, `write(input)`, `resize(input)`, `close(input): void`, `list(input): TerminalSession[]`, `attach(input): TerminalAttachResult`, `closeByProject(projectId): void`, `closeByRepository(repositoryId): void`, `shutdown(): void`.

- [ ] **Step 1:** `terminal-shell.ts` con `resolveShell`.
- [ ] **Step 2:** Servicio. Decisiones que fija el plan: mapa `Map<string, Live>` con `{ pty, ring, logStream, bytesLogged, truncated, session, startedAtMs, closing }`. `create`: comprueba límite de sesiones vivas (`TERMINAL_LIMIT`), resuelve repo→cwd (error `REPOSITORY_NOT_FOUND`), resuelve shell, inserta `executions` (`kind:'local_command'`, `context:'local'`, `status:'running'`, `command`=shell, `args`, `cwd`, `logPath`=`<userData>/terminal-logs/<executionId>.log`), `spawn` con `name:'xterm-256color'`, `useConpty` por defecto. Si `spawn` lanza, marcar la ejecución `failed` con `errorCode` y relanzar como `StewardServiceError('SPAWN_FAILED', …)`.
- [ ] **Step 3:** `onData` del pty: `redact()` del chunk, añadir al ring (recortando por el principio a `TERMINAL_RING_BYTES`), escribir al log mientras `bytesLogged < TERMINAL_LOG_CAP_BYTES` (al superar: `truncated=true`, escribir marca final, cerrar stream), y `emitData`. Para no partir secuencias UTF-8, usar `setEncoding('utf8')` o el decoder de node-pty (salida ya en string).
- [ ] **Step 4:** `onExit`: cerrar log, `updateExecutionFinish` (status `cancelled` si `closing`, `succeeded` si exit 0, `failed` si no), marcar la sesión `exited` con `exitCode`, `emitExit`. La sesión sigue en el mapa hasta `close`. `close` sobre sesión viva: `closing=true` y matar el árbol (`pty.kill()`; en Windows ConPTY mata hijos; si hace falta `taskkill /pid <pid> /T /F` vía `exec/run.ts`, nunca otro spawn). Sobre sesión ya muerta: solo la quita del mapa.
- [ ] **Step 5:** `write`/`resize` sobre sesión inexistente o `exited`: ignorar sin lanzar (`resize` además ignora dimensiones <1). `closeByProject`/`closeByRepository`/`shutdown` cierran sin esperar. Todo `updateExecutionFinish` tolera filas borradas por cascada.
- [ ] **Step 6:** `npm run check` → sin errores nuevos.

**Interfaces:**

- Produces: un handler por canal `terminal*`; `IpcContext` gana `terminal: TerminalService`. En `index.ts`: se crea el servicio con `emitData/emitExit` → `mainWindow?.webContents.send(TERMINAL_EVENTS.data|exit, payload)` (solo si la ventana existe y no está destruida); `app.on('will-quit')` llama `terminal.shutdown()`.
