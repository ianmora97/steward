# Sistema de UI estándar (M11.5): plan de implementación

> **Para quien ejecute:** usar `superpowers:subagent-driven-development` (recomendado) o `superpowers:executing-plans`. Los pasos usan casillas `- [ ]`.

**Objetivo:** un sistema de diseño propio (tokens + componentes + feedback + transiciones + zoom) y migrar toda la UI de Steward a él sin cambiar estructura ni comportamiento.

**Arquitectura:** `src/renderer/src/styles/` (tokens, base, motion) + primitivas en `src/renderer/src/components/` con los **mismos nombres de clase** que reemplazan (`.button`, `.iconbutton`, `.field`, `.empty`, `.banner`, `.dialog*`), de modo que el marcado viejo sigue funcionando mientras se migra pantalla por pantalla. Feedback con un store de toasts y un hook `useAction`. Zoom con un canal IPC nuevo que guarda el valor en la tabla `app_settings` que ya existe (sin migración).

**Stack:** Electron 45, React, Zustand, Zod, CSS plano. Sin dependencias nuevas.

**Spec:** `docs/superpowers/specs/2026-10-25-m11-5-ui-system-design.md`

## Restricciones globales

- **Sin pruebas automatizadas** (`CLAUDE.md` §1): no hay pasos de test ni TDD. Cada tarea se verifica con `npm run check` (typecheck + lint) y termina con la lista de **pruebas manuales** que hace el usuario. Nunca decir "listo" con el check roto.
- **Commits**: Conventional Commits, un commit por tarea, `CHANGELOG.md` actualizado en el mismo commit (bajo `Unreleased`, etiqueta `[M11.5]`). **Solo se commitea cuando el usuario lo pide.** Termina con `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
- Después de cada tarea: `graphify update .`. Al final: notas del vault (`Proyecto.md`, `Decisiones.md`, `Estado.md`).
- Respuestas al usuario en español, tono directo.
- Tokens: espaciado en múltiplos de 4 px (`--space-1…8` = 4, 8, 12, 16, 20, 24, 32, 48); radios `sm 5`, `md 8`, `lg 12`, `pill`; control `sm 28`, `md 32`, `lg 38`; movimiento `--dur-fast 120ms`, `--dur-base 180ms`, `--dur-slow 240ms`.
- El texto de un botón, pestaña o selector **nunca se parte** (`white-space: nowrap`); si no cabe, `IconButton` con `title` y `aria-label`, o `flex-wrap` en la fila. Las notas (`card__hint`) en filas centradas llevan `margin: 0`.
- Fechas y horas: solo `DateTimePicker`. Nada de `<input type="date|time|datetime-local">`.
- `@container` no admite variables CSS: umbrales fijos y comentados: compacto < 720 px, normal 720–1100 px, ancho > 1100 px. La vista compacta debe funcionar desde ~620 px.
- Sin `eslint-disable` ni `@ts-ignore` sin razón escrita. Imports de tipos con `import { type X }`. Comentarios solo para el porqué no obvio.
- Seguridad: solo el canal de zoom toca main; `ui:setZoom` valida con Zod un enum cerrado. Ningún secreto nuevo, ninguna red, ningún proceso hijo.

## Review Focus

Entradas o condiciones que el spec implica y ninguna tarea cubiría sola. Cada una tiene su comprobación manual en la tarea dueña.

1. Ráfaga de acciones (≥ 5 toasts seguidos): el viewport nunca muestra más de 4; salen primero los de éxito/info más antiguos; los de error no se pierden. → Tarea 2.
2. Una acción termina cuando su componente ya se desmontó (el usuario cambió de pestaña): sin warning de React ni estado huérfano, y el toast se muestra igual. → Tarea 2.
3. `ui.zoom` ausente, corrupto o fuera del enum en `app_settings`: arranca a 100 %; Ctrl `=` y Ctrl `+` (según teclado) suben el zoom; nunca sale de 80–150. → Tarea 2.
4. Ancho compacto (< 720 px de contenedor, y zoom 150 % con ventana de 940 px): badges y acciones de `ConnectionBar` hacen wrap, ningún botón parte su texto, nada desborda en horizontal. → cada tarea de pantalla.
5. Cargas rápidas (< 150 ms) no muestran skeleton; cargas lentas cuyo resultado llega justo al salir de la pantalla no dejan estado colgado; con `prefers-reduced-motion` el shimmer queda estático. → Tareas 2 y 3.

## Receta de migración de una pantalla (la usan las tareas 3–10)

Se aplica a cada `.tsx` y `.css` de la pantalla, en este orden:

1. `<button className="button …">` → `Button`; `className="iconbutton …"` → `IconButton` (con `label` obligatorio).
2. Todo pill, chip, badge o etiqueta de estado (`Pill`, `.chip*`, `.pill*`, `svcpill`, `mgtypechip`, `sshitem__badge`, `rdchip__badge`) → `Badge` si solo informa, `Chip` si se selecciona o se quita.
3. Cada texto "Loading…" / "Reading…" de primera carga → `Skeleton` con la forma del contenido, activado con `useDelayedFlag`. Cada botón de refrescar con datos visibles gira (`Spinner` o clase `is-spinning` en el icono) sin vaciar la vista.
4. Cada acción que cambia datos persistentes o remotos → `useAction` con texto de éxito (objeto + verbo en pasado) y `Button loading loadingLabel`; se borra el setter local `busy/saving/loading` que reemplaza. **No** llevan toast: stage/unstage, refrescar, seleccionar, abrir/cerrar paneles.
5. Cabeceras → `PageHeader` o `ConnectionBar`; bloques → `Card`; filas de lista → `ListRow`; formularios → `Field`; filas de botones → `Toolbar`.
6. CSS de la pantalla: `px` y colores hex → tokens; borrar reglas que ahora cubre una primitiva; dejar solo layout propio; `@media` por ancho de ventana → `@container`.
7. `npm run check` verde; `graphify update .`; línea de CHANGELOG; pruebas manuales de esa pantalla (ancho 940 px y zoom 150 % incluidos).

- **Cobertura del spec:** §1 → tarea 1; §2 → tarea 2; §3 → tareas 2–10; §4 → tareas 1–2 (tokens, `.enter`, `useExitAnimation`) y receta; §5 → tarea 2 (canal de zoom) y 4 (selector) y receta §6 (`@container`); §6 → tarea 3; §7 → orden de las tareas; seguridad → restricciones globales y tarea 2 paso 9; pruebas manuales → cada tarea y tarea 11.

- **Decisiones que el plan fija y el spec dejaba abiertas:** el zoom se guarda en la tabla `app_settings` existente (clave `ui.zoom`, sin migración nueva; la última migración es la m019); las primitivas reutilizan los nombres de clase actuales para poder migrar por pantallas sin romper nada.
